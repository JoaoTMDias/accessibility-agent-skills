# Núcleo portátil dos skills

Cada skill terá o seu núcleo portátil em `skills/<nome>/SKILL.md`. A instalação, permissões, invocação e integrações ficam em overlays específicos de Claude Code e Codex, em `overlays/<ambiente>/<nome>/`. Esta separação permite validar o mesmo conteúdo nos dois ambientes sem tornar o contrato dependente de um deles. Todos os skills incluem as sete secções, com títulos exactos: `Purpose and boundaries`, `Required inputs`, `Expected outcome`, `Sources`, `Optional tools`, `Limitations and uncertainty` e `Quality criteria`; quando uma não se aplicar, indicam-no explicitamente. Podem ter secções adicionais depois destas, desde que não alterem o significado do contrato comum. As fontes essenciais identificam URL directo, entidade responsável e versão ou data de consulta quando existir. Se uma fonte essencial não estiver disponível, o skill interrompe a parte dependente dela e declara essa limitação; não a substitui silenciosamente por memória ou fonte secundária. Quando faltarem entradas obrigatórias, o skill faz uma pergunta curta e não inventa nem assume informação crítica. Se uma ferramenta opcional não estiver disponível, o skill usa uma alternativa manual apenas quando ela produz evidência equivalente; caso contrário, declara a limitação. Um resultado de acessibilidade descreve a evidência, o método e os limites da avaliação; não a apresenta como conformidade geral sem essa base. A validação combina o verificador oficial da Agent Skills specification para o formato base com uma verificação do projecto para as sete secções. Um skill só está pronto para publicar quando passa ambas as validações; a revisão humana avalia a qualidade do conteúdo. O contrato é versionado separadamente com Semantic Versioning: uma versão major altera regras obrigatórias, uma minor acrescenta regras opcionais compatíveis e uma patch apenas clarifica o texto. Uma alteração major migra todos os skills do repositório na mesma alteração; não se suportam contratos mistos.
